# 接続コンテキスト表示（pane_context）

「このペインはどこに繋がっているか」を、ペインのヘッダーと画面下部のステータスバーに
常時表示する機能です（Phase 4.4.4）。

隣り合った 2 つのペインは見た目が同じでも、片方は本番アカウント、片方は検証アカウントを
向いていることがあります。`aws s3 rm` を打つ前に「今どこにいるか」を確認するために
`aws sts get-caller-identity` を叩き直す、という手順を無くすのがこの機能の目的です。

## 何が表示されるか

ペインヘッダーは、既存の表示（状態ドット・ペイン名・CPU/メモリ）の間にチップが並びます。

```
 ● ▪ claude #2   ⇄ deploy@web-01   ☁ prod-admin · ap-northeast-1   ◍ qwen3-coder   ⑂ main   ▸ …/project/ptygrid   CPU 3.1% · 412 MiB   ⟳ ⤢ ✕
```

| チップ | 記号 | 内容 | 色 |
|---|---|---|---|
| リモート接続先 | `⇄` | `ssh` / `sftp` / `scp` / `mosh` / `telnet` の接続先、`kubectl` / `docker exec` の対象 | 黄 |
| AWS | `☁` | プロファイル（と、あればリージョン） | 橙 |
| モデル | `◍` | エージェント CLI が話している LLM のモデル名（無ければエンドポイント） | 水色 |
| ブランチ | `⑂` | git のブランチ名。detached HEAD は `@a1b2c3d` | 緑 |
| ディレクトリ | `▸` | 作業ディレクトリ（末尾 2 階層。ホームは `~`） | 灰 |

**並び順は「実行結果を変える度合いの高い順」**です。ペインが狭いときはチップが右から
欠けるので、リモート接続先と AWS プロファイルが最後まで残ります。省略された値は
チップにマウスを乗せれば全文がツールチップで出ます。

### ステータスバー

画面下部のバーには、**最後にフォーカスしたペイン**の同じチップが省略なしで並びます
（ペインが 1 枚だけのときは、フォーカスしていなくてもそのペインを表示します）。
バー左端のペイン名をクリックすると、該当ペインの枠が一瞬ハイライトされるので、
9 分割していても「今どのペインの話をしているか」がすぐ分かります。

### 表示されない場合

- 値が解決できなかったチップは**出ません**（空のチップは置きません）
- ペインが終了（`exit`）すると、そのペインのチップは即座に消えます。古い接続先が
  残り続けることはありません
- worktree バッジ（`⑂ ブランチ名`）を持つペインでは、ブランチチップは出ません
  （同じ内容の二重表示を避けるため）

## 有効化と設定

**既定で有効です。** 何も書かなくても動きます。

止めたい・間隔を変えたいときだけ、`ptygrid.yml` にブロックを足します。

```yaml
pane_context:
  enabled: true       # 既定 true。false で表示とサンプリングを完全に停止
  interval_ms: 5000   # 既定 5000。1000〜60000 にクランプされる
```

| 設定 | 効果 |
|---|---|
| 省略 | 既定（有効・5 秒間隔） |
| `enabled: false` | チップが全て消える。バックグラウンドのサンプリングも止まる |
| `interval_ms: 1000` | 最短。`cd` した直後の追従が速くなる代わりに、プロセス情報の読み取り頻度が上がる |
| `interval_ms: 30000` | 表示は 30 秒遅れで追従する。オーバーヘッドを最小にしたいとき |

設定はホットリロードされます。ptygrid.yml を保存してツールバーから読み込み直すと、
**アプリを再起動せずに**次のサンプリングから効きます。

> CPU / メモリの表示（`session-resources`）は 1 秒間隔で別途動いており、この設定の
> 影響を受けません。接続コンテキストだけが遅い周期で回ります。

## 情報源と更新タイミング

| チップ | 情報源 | 追従の速さ |
|---|---|---|
| リモート接続先 | フォアグラウンドプロセスのコマンドライン | 1 秒（従来からの表示） |
| ディレクトリ | フォアグラウンドプロセスの実際の cwd（取得できないときはペイン起動時の cwd） | `interval_ms`（既定 5 秒） |
| ブランチ | ディレクトリから上位に向かって `.git` を探し `HEAD` を読む | `interval_ms` |
| AWS | プロセスの環境変数（許可リストのみ） | `interval_ms` ＋ 後述の制約 |
| モデル | 同上 | `interval_ms` ＋ 後述の制約 |

ブランチの判定は `git` コマンドを起動せず、`.git/HEAD` を読むだけです。linked worktree の
`.git` ファイル（`gitdir:` ポインタ）も辿るので、worktree 分離を使っているペインでも
正しいブランチが出ます。

モデルの判定は、環境変数のどの系統が入っているかで決まります（上から順に優先）。

| provider | 見る変数 |
|---|---|
| `anthropic` | `ANTHROPIC_BASE_URL` / `ANTHROPIC_MODEL` |
| `openai` | `OPENAI_BASE_URL` / `OPENAI_MODEL` |
| `ollama` | `OLLAMA_HOST` |

エンドポイントが `127.0.0.1` / `localhost` / `::1` / `*.local` を指している場合は
**ローカルエンドポイント**と判定され、ツールチップにその旨が出ます。claude-code-router
経由でローカル LLM に流しているのか、クラウドに出ているのかが一目で分かります。

## 使い方のレシピ

### AWS のアカウント取り違えを防ぐ

`direnv` と組み合わせるのが一番確実です。プロジェクトのルートに `.envrc` を置きます。

```bash
# .envrc（.gitignore に入れること）
export AWS_PROFILE=ptygrid-dev
export AWS_REGION=ap-northeast-1
```

```bash
direnv allow
```

このディレクトリで開いたペインからコマンドを実行すると、`☁ ptygrid-dev · ap-northeast-1`
が出ます。本番用のプロファイル名は `prod` を含む名前にしておくと、チップの文字列だけで
判別できます。

`aws-vault` を使っている場合は `AWS_VAULT` 環境変数が見られるので、
`aws-vault exec prod -- ...` の実行中もプロファイル名が出ます。

### ローカル LLM に向いているか確認する

```bash
ANTHROPIC_BASE_URL=http://127.0.0.1:3456 ANTHROPIC_MODEL=qwen3-coder claude
```

`◍ qwen3-coder` が出て、ツールチップに `@ 127.0.0.1:3456（ローカルエンドポイント）`
と表示されます。ルーターが落ちていてクラウドにフォールバックした場合は、次の
サンプリングでエンドポイントの表示が変わるので気づけます。

### 踏み台の先を間違えない

`ssh deploy@web-01` を実行すると `⇄ deploy@web-01`。`kubectl exec -n prod pod/api` なら
`⇄ exec prod/api`。ペインタイトル側にも同じ情報が出るため、ペインを最大化していない
状態でも取り違えにくくなります。

### 動作確認

一番手軽な確認方法は、環境変数を付けて `sleep` を走らせることです。

```bash
AWS_PROFILE=demo-prod AWS_REGION=ap-northeast-1 sleep 30
```

5 秒以内にチップが出て、`sleep` が終わると消えます。

## 既知の制約: 環境変数が出るタイミング

**OS はプロセスの環境変数を「起動した時点の値」でしか公開しません**
（Linux は `/proc/<pid>/environ`、macOS は `KERN_PROCARGS2`）。ptygrid が後から
覗き見る方法はありません。

その結果、こうなります。

| 状況 | AWS / モデルのチップ |
|---|---|
| `ptygrid.yml` の `agents[].env` で渡した値 | ペイン起動直後から出る |
| ペイン内で何かコマンドを実行している間 | 出る（子プロセスが現在の環境を持つため） |
| direnv や `export` で後から設定し、シェルのプロンプトで待っている間 | **出ない** |

つまり「direnv を設定したのにチップが出ない」のは不具合ではなく、**何かコマンドを
走らせた瞬間から出ます**。プロファイルを常時出しておきたい場合は、`ptygrid.yml` 側で
エージェント定義に `env` を書くのが確実です。

```yaml
agents:
  - name: claude
    cmd: "claude"
    cwd: "."
    env:
      AWS_PROFILE: "ptygrid-dev"
      AWS_REGION: "ap-northeast-1"
```

**作業ディレクトリとブランチにはこの制約はありません。** 毎回ライブに読むので、
`cd` すれば次のサンプリングで必ず追従します。

## 秘密情報の扱い

環境変数を読む機能なので、設計上の境界を明示しておきます。

1. **読むのは固定の許可リストだけ**です。以下の 10 個以外は一切読みません。

   `AWS_PROFILE` / `AWS_DEFAULT_PROFILE` / `AWS_VAULT` / `AWS_REGION` /
   `AWS_DEFAULT_REGION` / `ANTHROPIC_BASE_URL` / `ANTHROPIC_MODEL` /
   `OPENAI_BASE_URL` / `OPENAI_MODEL` / `OLLAMA_HOST`

2. **名前が資格情報らしいキーは、許可リストに載っていても捨てます。**
   `KEY` / `TOKEN` / `SECRET` / `PASSWORD` / `PASSWD` / `CREDENTIAL` / `SESSION` を
   名前に含むものが対象です。許可リストの編集ミスに対する二重の防壁で、許可リスト自体が
   この規則に違反していないことも自動テストで検証しています。

3. **エンドポイント URL は userinfo を落として表示します。**
   `https://tok@host:8443/v1` は `host:8443` としか出ません。

つまり `AWS_SECRET_ACCESS_KEY` や `ANTHROPIC_API_KEY` は、チップにもツールチップにも
フロントエンドに渡るデータにも一切現れません。画面共有やスクリーンショットでも安全です。

止めたい場合は `pane_context: { enabled: false }` で、環境変数の読み取りごと停止できます。

## 表示されないときの切り分け

| 症状 | 見るところ |
|---|---|
| チップが 1 つも出ない | `ptygrid.yml` に `pane_context: enabled: false` を書いていないか。設定が実際に読み込まれているか（ツールバーの設定バッジ） |
| ディレクトリ（`▸`）だけ出ない | macOS がプロセスの cwd 取得を拒否している可能性。`lsof -a -w -d cwd -Fn -p <ペインのpid>` を手で叩いて確認する |
| AWS（`☁`）が出ない | 上の「既知の制約」。`AWS_PROFILE=x sleep 30` で切り分ける |
| ブランチ（`⑂`）が出ない | そのディレクトリが git リポジトリの中か。worktree ペインではバッジ側に出るため意図的に非表示 |
| 反映が遅い | `interval_ms` の既定は 5 秒。`1000` にすると最短 1 秒になる |
| 終了したペインに古い値が残る | 起きないはず。起きたら不具合として報告してください |
